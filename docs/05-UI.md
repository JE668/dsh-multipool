# 05 · UI（左栏图标 + 浮层 + BI 看板 + 设置面板）

> 决策来源：D5（看板 B 方案 = `main` 主面板 + `shell.overlay` 全屏层，双注册，设置里开关）、D6（额度耗尽 = 往会话插系统提示）、D4（事件 30 天）。
> 原则：**数字必须带来源徽标**；上游没有的字段显示 `—` / `(未提供)`，绝不显示 `0` 冒充「用完了」。

|---|---|---|

## 2. 左栏图标（`sidebar.panellist`）

### 2.1 视觉

```
┌──────┐
│  ◕   │ ← 24×24 线性图标，中线双环（示意「池 + 限流」）
│  3   │ ← 右下角数字徽标：可用账号数（available / total）
└──────┘
       ● 颜色：绿(全通) / 黄(部分冷却,存在可用) / 红(全部不可用) / 灰(未配置 Key)
```

### 2.2 徽标语义（明确到不歧义）

| 徽标 | 含义 | 数据来源 |
|---|---|---|
| `3` | available 账号 / 全部账号 = 3/5 | `Account.status` |
| 红点 | 近 5 分钟 429 率 > 30% | `MetricsEvent` 聚合 |
| 黄点 | 存在账号 `quota_unknown` 或某账号剩余额度 < 10% | AMD:`/v1/usage`；其他：本地估算 |
| 灰态 | 五家全都没填 Key | 设置 |

### 2.3 悬浮 tooltip（收窄成图标栏时唯一的信息面）

窄屏（DSH 左栏折叠）时浮层**不可用**，tooltip 必须自给自足，固定三行：

```
可用账号 3/5（AMD 2 · NIM 1 · SenseNova — · Agnes —）
全局 RPM 余量 65%（11 / 17）
今日 pts 剩余 4.19 / 10（AMD 2 号，北京时间 00:00 重置）
```

- 无数据的 Provider **不写 0**，写 `—` 并在括号里注 `无端点`。
- tooltip 用纯文本，不做富交互（图标栏模式下点击事件会被 DSH 吞）。

## 3. 浮层 Popover（紧凑摘要）

宽 320px，从上到下四段，每段都可折叠，状态持久化到 settings。

### 3.1 段 1 · 全局

```
活跃会话 4      可用账号 3/5
判断 429 率（5m） 0.8%      排队中 1
```

### 3.2 段 2 · Provider 卡片（5 张，按需展开）

每张卡片固定三行，**行数固定、字段固定**，五家卡片形状一致。

```
AMD Radeon Cloud            2/2  ●　可用
  RPM  11/20 进  [▓▓▓▓▓▓░░░░] 55%
  日额度 4.19 / 10 pts  [▓▓▓▓░░░░░░] 42%  00:00 重置
  429  近 1h 2 次（gateway RPM 2 · daily 0）
```

| Provider | 第 1 行（每分钟速率） | 第 2 行（额度） | 第 3 行（限流事件） |
|---|---|---|---|
| AMD | 账号 RPM 已用/20（来源：响应头或本地窗） | 今日 pts 已用/上限 + 重置时刻 | 分三类：平台 / 网关 RPM / 日额度 |
| NIM | 本地 60s 窗 已用/预算 40（标「本地」） | `—（上游未提供用量端点）` | 近 1h 429 次数 |
| SenseNova | 本地预算 3（标「学习值 → 上调中」） | 积分：通用池/专属池（上仅当用户手填，否则 `—`） | 近 1h 429 次数 + 当前退避剩余 |
| Agnes | 已用/档位 RPM（免费 20） | 5h 窗口剩余：仅当有 402 记录/手填，否则 `—` | 近 1h 429；近 24h 402 |
| Google | 逐模型 RPM 已用/上限（标「上游指标」，上游不给已用量时显 `—` 加「本地推算」） | 逐模型 RPD 已用/上限 + 太平洋时间重置时刻；无 RPD 额度的模型显 `Free 档不可用` | 近 1h 429 次数（本地限流）与 `RESOURCE_EXHAUSTED`（上游无额度）分开计 |

- 数值右上角的小徽标：`A`=从响应头/端点读到的实时值、`L`=本地估算、`U`=用户手填、`?`=未知。Google 的 RPM / TPM / RPD 上限属于「上游指标」，与已用量同时展示时必须写成「已用 / 上限」，不得把上限伪装成剩余量。鼠标悬停给一句话解释。
- 「RPM 已用」对 AMD 优先信 `X-RateLimit-Remaining-User-RPM`（实时），头缺失时退化到本地窗口并显示 `L`。

### 3.3 段 3 · 排队与冷却

```
排队中 1 条    预计 12s 后可发
冷却中 2 个账号
  AMD-2  gateway RPM  剩 41s
  NV-1   upstream 5xx 剩 1m 20s
```

### 3.4 段 4 · 入口

`[打开看板]  [设置]` —— 最常用两个动作放最后一行。

## 4. BI 看板

### 4.1 形态

- **3a 整页**（默认）：`main` 面板，panel id `dsh-multipool-dashboard`；左栏保留，可随时切回会话。
- **3b 沉浸**：`shell.overlay` 全屏；`Esc` 退出；进入时**暂停**任何会挤占上游配额的后台刷新（看板只读本地聚合，天然不受影响，但显式声明一次）。
- 两种形态共用**同一个** `<Dashboard />` 根组件与同一套查询函数，只换外层容器。

### 4.2 布局（桌面 ≥1280px）

```
┌──────────────────────────────────────────────────────────────┐
│ 顶部筛选栏  [时间 ▾15m/1h/24h/7d/30d]  [Provider ▾] [Model ▾]  │
│             [自动刷新 ⟳ 30s]  [导出 JSON]                     │
├──────────────────────────────────────────────────────────────┤
│ KPI 行（6 张卡）                                               │
│ 总请求 4,281 │ 429 率 0.8% │ 输入 tok 1.9M │ 输出 tok 640K     │
│ pts 已用 6.2/10 │ 可用账号 3/5                                │
├──────────────────────────────────────────────────────────────┤
│ ① 请求与 429 类型曲线（双轴折线 + 堆叠面积）                    │
│ ② RPM 使用（每账号一条线 + 预算虚线）                          │
├──────────────────────────────────────────────────────────────┤
│ ③ 并发（每账号一条线 + 并发上限虚线）  ④ 队列等待时长 热力图    │
├──────────────────────────────────────────────────────────────┤
│ ⑤ Provider × Model 流向桑基图  ⑥ 学习画像表（RPM/样本/置信）   │
├──────────────────────────────────────────────────────────────┤
│ ⑦ 账号明细表（可排序/可筛选）                                   │
└──────────────────────────────────────────────────────────────┘
```

### 4.3 卡片与图表契约

| 区块 | 图表 | 数据 |
|---|---|---|
| KPI ×6 | 大数字 + 24h 迷你 sparkline | `MetricsResult.kpis`；`estimatedCostPts===null` 时显示 `—` 并附「无单价来源」 |
| ① 请求 & 429 | ECharts 双轴折线（请求）+ 堆叠面积（`err429ByKind`） | `series[]`，按 `bucket` |
| ② RPM | 折线（每账号一色）+ 水平虚线（预算） | 由 `MetricsEvent.ts` 按分钟滑动窗算 |
| ③ 并发 | 折线（每账号） | 由事件 `start/end` 推得（`concurrencyAtSend` 采样） |
| ④ 队列等待 | 热力图（x=时间, y=秒） | `queueWaitMs` |
| ⑤ 桑基 | Provider → Model → 状态 | 组合计数，**不做成本桑基**（ADR-8：费用不在前提范围） |
| ⑥ 学习画像 | 表 | `learnedProfiles[]`；`confidence` 用色点，样本少标「低」 |
| ⑦ 明细 | 表 | `accountSnapshot[]`；所有缺失字段渲染 `—`，不可排序 |

- **主题**：ECharts 用 CSS 变量取色（跟随 DSH 亮/暗主题），不硬编码色值。
- **空数据**：某个 Provider 无任何事件时，图表区显示 `暂无数据（未配置 Key / 未发起请求）`，不是 0 值空图。
- **折线断裂**：`promptTokens` 为 `undefined` 的桶，`connectNulls: false`，让线断开。
- **自动刷新**：默认 30s 只重跑本地查询（`06-TASKS` 中叫 `liveTick`），**绝不**触发 `/v1/usage` 等上游请求。

### 4.4 图表库选型

| 候选 | 结论 |
|---|---|
| ECharts（`dsh-visualizer` / `dsh-echarts` 用过） | **推荐**：桑基、热力、双轴、个性化样式都稳，且 DSH 生态已验证「option 能用纯 JSON 表达」即可渲染 |
| Recharts（`dsh-dashboard` 用过） | 可做 KPI 卡与简单折线，但桑基需额外库 → 与 ECharts 二选时不如一个库 |
| 两者混用 | **禁止**：包体积与主题双份维护 |

→ stat card 用原生 React + DSH 现有卡片组件；所有图表走 ECharts 单实例多 setOption 或按需分包。

### 4.5 交互

- 点击某个 Provider 卡片 → 顶部 Provider 筛选只留它（再点取消）。
- 点击 KPI「429 率」→ ① 图只开 429 堆叠。
- ⑦ 明细表行内 `More` → 展开该账号近 30 分钟事件（只读本地，最多 200 条）。
- 导出 JSON：时间范围 + 板块（KPI / ①-⑦）+ 是否含 Key 掩码始终为「含且仅掩码」。

## 5. 设置面板

Host 侧在 `ctx.inject(['settings'], child => child.effect(...))` 子上下文里调 `ctx.settings.configure({auto:false}, ctx.fiber)` 注册命名空间 `dsh-multipool` 并关闭自动页；Client 侧 `ctx.slots.inject('settings.section', () => ctx.slots.register({ name:'settings.section', id:'dsh-multipool-amd', order:30, label: () => t('nav'), locale: NS, inject: sectionInjected, children: {...} }, AmdSettingsSection))` 注册独立设置页（ADR-11）。全部字段热生效，`applies:'restart'` 仅一个（端口）。

> **已知差异（DSH 0.2.2-rc.3 实测）**：本文旧版写的 `settings.installSection`（Host）与 `settings.plugin.item`（Client）**在该版本不存在**，`dsh-doc` 的槽位源码里也没有。真实可用的是 `settings.section` / `settings.section.icon` / `settings.plugins.tab` / `settings.general.item` / `settings.onboarding`。其余本文件用到的槽位也已核对：`sidebar.panellist`（owner props `{size, active}`，注册需带 `id`/`order`/`label`/`locale`）、`shell.overlay`（list/root，点击穿透）、`main`（keyed/root，key 为 `MainPanelId`）——均已按真实签名核对。

### 5.2 全局调度

| 项 | 默认 | 说明 |
|---|---|---|
| 会话粘性 | 开 | 关掉等于每次 leastLoad，缓存命中必掉 |
| 粘性空闲 TTL | 30 分钟 | 超时后新请求重新按负载选 |
| 迁移偏置 `MIGRATION_BIAS` | AMD 3.0 / 其他 1.0 | §3.4 代价权衡 |
| 短等阈值 `maxWaitMs` | 60s | 超此阈值才返 503 |
| 单次请求最大尝试 | 3 | 之后回 429 包装错误 |
| 抖动系数 | 0.15 | Retry-After 乘数上界 |
| 跨 Provider 故障转移 | 关 | 开启需二次确认 + 红字警告 |
| 假设外部客户端数 | 1.5 | 闸 1 预算要除以它（§7） |
| 额度耗尽提示 | 会话内插系统提示 | D6 |

### 5.3 看板

| 项 | 默认 |
|---|---|
| Computation 形态 | B 方案：整页 `main` + 「沉浸全屏」开关走 `shell.overlay` |
| 默认形态 | 整页 |
| 自动刷新间隔 | 30s（只刷本地聚合） |
| 事件保留 | 30 天（D4），到期滚动清理，每日级汇总长期 |
| 暗色/亮色 | 跟随 DSH |
| 图表库 | ECharts（禁用 Recharts） |

### 5.4 设置页的错误防控

- 端口/Base URL **不可编辑**（防错配），仅显示并给「复制」。
- Key 输入框：粘贴即脱敏回显；`rejected_key`（sk- 开头填进 AMD、或填成实例域名）给红字说明并**拒绝保存**。
- 保存前跑一次「预算自检」：若 `并发上限 > 官方硬帽` 或 `RPM 预算 > 官方上限`，阻止保存并提示依据。

## 6. 空态 / 错误态 / 降级态（必做，否则看起来像 Bug）

| 场景 | 展示 |
|---|---|
| 一个 Key 都没配 | 图标灰；浮层只有「+ 添加第一个账号」，五个 Provider 卡片隐藏 |
| 某 Provider 无账号 | 该卡片不出现（不是显示 0%） |
| 用量端点 `no-endpoint`（NIM） | 额度行显示 `—  官方未提供用量接口` |
| 用量端点 `no-endpoint`（SenseNova） | 额度行显示 `—  仅账户页可见`，旁边给「打开控制台」外链 |
| 用量端点 `no-endpoint`（Google） | 额度行显示 `—  官方未提供用量接口`；Google 只给速率限制上限不给已用量，已用量只能由本地计数推算，必须标 `本地推算`，**不得显示 0** |
| Google 免费档没有该模型的额度（含图像 / 音乐 / 视频 / deep-research / computer-use 类） | 该模型卡片不显示速率与额度，只显示灰标 `Free 档不可用`；不要与「限流」混为一谈 |
| Live 类模型限制 | 模型行单独标注 `仅实时链路`；不进聊天模型选择器 |
| Agnes 无额度 API | 显示「5h 窗口：未知（按 402 学习）」，并在首次 402 后改为「已耗尽 · 重置约 xx:xx」 |
| `/v1/usage` 502（AMD 官方：当作未知不是零） | 保留上一次数值 + 角标「未知（网络/服务）」+ 时间戳；**绝不写 0** |
| 模型目录拉取失败 | 用本地 `catalog/` 快照，顶部黄条「目录为 2026-11-17 快照，模型列表可能过期」 |
| 全部账号冷却 / 熔断 | 图标红；浮层首行红字「上游暂不可用，N 秒后重试」；看板照常展示历史 |
| 某账号 401/403 | 明细行标 `auth_failed`，给「重新粘贴 Key」按钮，**不自动重试** |
| 某次 429 因 `rpm_ip` | 浮层顶部横幅「同出口 IP 已达上限（120 RPM），所有 AMD 账号受影响」 |
| SenseNova 429 | 横幅「已降速至 x RPM，xx 秒后重试（原因不可区分：速率/额度）」 |

## 7. 让 DSH 侧看得见的事（D6 会话内提示）

不只在插件 UI 里提示，还要让**正在聊天的用户**知道：

- 某账号额度耗尽/长期冷却 → 往当前会话插一条**系统提示**（DSH 支持的系统角色消息）：
  > `dsh-multipool: AMD-B 今日 pts 额度已用尽（北京时间 00:00 重置）。该会话已切换到 AMD-A，前缀缓存将重新建立，本次可能多消耗约 X pts。`
- 若**无可用账号**、插件返回 503/包装 429 → 系统提示里带 `retryAfterMs` 与建议动作。
- 提示插入频率限流（同一会话同类提示 10 分钟内最多 1 条），防止刷屏。

## 8. 可访问性与可读性（小项但别漏）

- 颜色不是唯一编码：429 / 冷却 / 耗尽除红黄绿外，再给形状或图标（▲ 冷却、■ 耗尽）。
- 图标 tooltip 支持键盘 focus。
- 数字用等宽字体，右对齐，避免看板列跳动。
- 时间统一显示 `Asia/Shanghai`，并在 tooltip 里给 UTC（AMD 的 `daily_reset_at` 带偏移，展示时不改写）。
