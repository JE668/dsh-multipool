## 五条铁律（任何文件冲突时，以本条为准）

1. **不编造事实。** 限制数值、响应头名、端点路径、错误码，只能来自 ①官方文档逐字核对 ②本地资料文件逐字核对 ③对 live 端点实测。三者都没有的，标 `unknown`，不填默认值、不写「大约」、不拿别的 Provider 类推。
2. **来源随值走。** 每个进入 UI 或参与决策的字段都带 `source`：`api` / `doc` / `doc-local` / `learned` / `user` / `unknown`，UI 必须可见。
3. **冲突并排显示，不静默择一。** 同一事实两个来源不一致时，两个都显示并标来源。
4. **上游给的 `Retry-After` 优先于本地一切启发式。** 本地限流只决定「发出去之前等多久」，绝不能覆盖或缩短上游给的冷却。
5. **宁可少发一条请求，也不发一条注定 429 的请求；宁可 UI 少显示一个数，也不显示一个编出来的数。**

## 引用约定（给人和给创造模式都适用）

本套文档里的章节**只在文档内部自引用时**写成裸 `§x.y`（例如：

- `04-SCHEDULER.md` 里写 `§3.2`，指的是 04 自己的 §3.2；
- `07-ACCEPTANCE.md` 里写 `§5.1`，指 07 自己的 §5.1）。

**跨文件引用一律带文件名前缀**：`02 §1.7`、`03 §3`、`04 §9`、`06 T-1-i`、`07 A-15`。

- 只写 `§1.7` 时，先在本文件里找 `## 1.` / `### 1.7`，找不到再往上下文最近一次出现的「NN §」里的 NN 找。
- **找不到就是引用错误，不要猜。**把该处标出来告诉用户（文档名 + 行号 + 引用串），由用户决定改成哪个章节。
- 「04 §8」这类引用不要去找 02 的第 8 节，它实际是 `04-SCHEDULER.md` 的 §8（已知错误 / 教训），已在 2026-11-17 一轮修正里逐条改过；若再看到，按 04 §8 理解并回报。
