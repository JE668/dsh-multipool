## 五条铁律（任何文件冲突时，以本条为准）

1. **不编造事实。** 限制数值、响应头名、端点路径、错误码，只能来自 ①官方文档逐字核对 ②本地资料文件逐字核对 ③对 live 端点实测。三者都没有的，标 `unknown`，不填默认值、不写「大约」、不拿别的 Provider 类推。
2. **来源随值走。** 每个进入 UI 或参与决策的字段都带 `source`：`api` / `doc` / `doc-local` / `learned` / `user` / `unknown`，UI 必须可见。
3. **冲突并排显示，不静默择一。** 同一事实两个来源不一致时，两个都显示并标来源。
4. **上游给的 `Retry-After` 优先于本地一切启发式。** 本地限流只决定「发出去之前等多久」，绝不能覆盖或缩短上游给的冷却。
5. **宁可少发一条请求，也不发一条注定 429 的请求；宁可 UI 少显示一个数，也不显示一个编出来的数。**

## 用户已确认的决策（2026-11-17）

| 编号 | 决策 |
|---|---|
| D1 | 四个 Provider **都可能是多账号**，约定 **一号一个 Key**（同账号多 Key 不用于扩容） |
| D2 | Agnes 用户在**免费档**，Key 实际以 **`sk-`** 开头（不是文档/社区口径的 `cpk-`） |
| D3 | 看板采用**方案 B**：主面板 `main` + 全屏覆盖层 `shell.overlay` 双注册，设置里可切换 |
| D4 | 请求级事件**保留 30 天**，日级聚合长期保留 |
| D5 | 某 Key 额度耗尽时，**在会话里插入一条系统提示**（告知已切换） |
| D6 | SenseNova 收到 429 采用**降速**方案：**不**整账户暂停到 5h 边界，只降低本账户速率并退避 |
| D7 | 项目名前缀 `dsh-`，本项目名 **`dsh-multipool`** |
